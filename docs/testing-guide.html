Two-person rules and roles that can't be combined

One prepares, another verifies
  • Loan: Loan Officer verifies and recommends → Management approves
  • Disbursement voucher: Cashier → Finance Manager
  • Schedule correction: Treasurer → Finance Manager
  • Source Advice (Finance Manager) is checked against the schedule (Treasurer)
  • Bank charge, interest or transfer: Cashier → Finance Manager
  • Bank opening balance: Admin → Finance Manager
  • Financial setting: Admin proposes → Management approves
  • Lodgement: Finance Manager verifies at the bank → Cashier records
Never the same person
  • Cashier + Finance Manager
  • Treasurer + Finance Manager
  • Management + Cashier
  • Management + Loan Officer
  • Secretary + Loan Officer
  • Admin or GMD with any other role
  • Staff never act on their own loan or membership

Scenarios to test

Each follows a real situation across the actors involved, with what should happen and the mistakes the system must refuse.

1

From invitation to member

Secretary → Applicant → Admin (outbox) → Loan Officer → Member

  1. Secretary: Invitations → invite a new person (any 080… number) with source DEMO-PAYROLL.
  2. Admin: Staging outbox → copy the invitation link; open it in a private window.
  3. Applicant: request the code, read it in the outbox, fill the form, upload 7-sample-id-card.jpg, set a password.
  4. Loan Officer: Members → record the payroll staff number (e.g. S05001) → Activate.
  5. Member: sign in on the Member tab.

ExpectThe member is ACTIVE with a member number (MCS-…); an activation SMS appears in the outbox.

Try to break it
  • Loan Officer: try Activate before recording the staff number (refused).
  • Applicant: open the same link again after registering (refused).
  • Secretary: invite the same phone twice (refused).
